# Intent MILEAGE: проверка пробега в расчёте решения по заявке

- ID задачи: `MILEAGE` (день 1, ДЗ.1)
- Дата: 2026-09-29, собран после интервью Grill Me с заказчиком
- Исходная формулировка: «добавить в расчёт решения по заявке проверку — пробег авто не больше 400 000 км, иначе решение review»

## 1. Замысел

Добавить в расчёт решения по заявке (`approve` / `review` / `reject`) проверку пробега автомобиля: если пробег больше 400 000 км, заявка не получает автоматическое одобрение — решение `review`.

Расширение по итогам интервью: пустое или нечисловое значение пробега — ошибка валидации заявки, а не молчаливый «0 км».

## 2. Зачем

Сейчас решение зависит только от LTV, пробег на него не влияет никак: заявка с любым пробегом может получить `approve` — код: `backend/src/Domain/DecisionEngine.php`, `backend/src/Domain/ApplicationValidator.php`. Задача закрывает пробел: авто с пробегом больше 400 000 км не одобряются автоматически, а уходят в `review`.

## 3. Constraints

- Порог — 400 000 км; «не больше 400 000» — включительно: 400 000 ещё норма, `review` начинается с 400 001. — ответ в интервью.
- Правило понижает до `review` только `approve`; зоны `review` и `reject` по LTV не меняются, `reject` не смягчается. — ответ в интервью.
- Расчёт LTV и его пороги не меняются: правило применяется к решению по LTV, а не к расчёту. — ответ в интервью; код: `backend/config/rules.php`.
- Пробег в заявке отсутствует → ошибка валидации, решение не считается (существующее поведение). — код: `backend/src/Domain/ApplicationValidator.php`.
- Пустая строка или нечисловое значение пробега → ошибка валидации (422), а не «0 км»; сейчас пустая строка превращается в 0 и проходит. — ответ в интервью; код: `backend/src/Domain/ApplicationValidator.php`, `backend/src/Http/ApplicationController.php`.
- Валидационный диапазон пробега 0–500 000 км остаётся: свыше 500 000 — ошибка валидации, до решения заявка не доходит; новое правило этот предел не заменяет. — код: `backend/config/rules.php`, `backend/src/Domain/ApplicationValidator.php`.

## 4. Open questions

- Граница «не больше 400 000» — закрыт заказчиком (интервью): 400 000 проходит, `review` с 400 001.
- Перекрывает ли правило `reject` — закрыт заказчиком (интервью): нет, `reject` остаётся `reject`.
- Пустой/нечисловой пробег — закрыт заказчиком (интервью): ошибка валидации 422.
- Причина решения в ответе API (например, `reason: "high_mileage"`) — открыт: заказчик переадресовал архитектору, в задачу MILEAGE не входит.

## 5. Не входит

- Поле причины решения в ответе API — переадресовано архитектору. — ответ в интервью.
- Изменение валидационного предела пробега 500 000 км и остальных существующих порогов (LTV, год, сумма, срок). — код: `backend/config/rules.php`.
- Ужесточение валидации остальных полей заявки (VIN, год, стоимость, сумма, срок) — меняется только пробег. — формулировка задачи.
- Изменения фронтенда и БД: поле пробега в форме и колонка в БД уже есть. — код: `frontend/index.html`, `db/schema.sql`.
- Расчёт лимита по возрасту авто (`ltv_by_age`) — отдельная задача LOAN-12. — код: `backend/config/rules.php`.
